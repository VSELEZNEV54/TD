# TeacherDesk: сайт и бэкенд

Здесь находятся готовый фронтенд сайта, исходники его генератора и Python-бэкенд вопросов и консультаций с SQLite и закрытой панелью обращений. Учетные записи и учебный кабинет самой платформы работают в отдельном приложении `app.teacherdesk.ru`.

Текущий полный пакет для проверки находится в ветке **`dev`**. В `main` изменения переносятся после приемки через Pull Request. Для просмотра сохранены все 57 страниц, включая страницы-примеры.

## Что где лежит

| Путь | Назначение |
| --- | --- |
| `site/` | Готовый сайт: HTML, CSS, JavaScript, шрифты и изображения |
| `server/` | Вопросы и консультации, API, SQLite, закрытая панель `/admin/` |
| `deploy/` | Упаковка, экспорт для Pages, nginx, Gunicorn и systemd |
| `Dockerfile`, `compose.yaml`, `requirements.txt` | Запуск сайта вместе с бэкендом |
| `.env.example` | Пример настроек без секретов |
| `build/` | Исходники генератора и контент страниц, для запуска сервера не нужны |
| `tests/` | Проверки бэкенда и экспорта для Pages |
| `docs/` | Дизайн-система, факты о продукте и инструкции |
| `.github/workflows/site.yml` | Автоматическая проверка, ZIP сервера и подготовка Pages |
| `prototype/`, корневые `index.html` и `404.html` | Архив старого прототипа и его вход, не актуальный сайт |

Локальный `.env`, обращения, базы данных, резервные копии и виртуальное окружение в Git не входят. Для рабочей версии используйте `site/`, а не корневой `index.html` репозитория.

## 1. Проверить весь проект локально

Нужен Python 3.9 или новее. Встроенный сервер работает без установки зависимостей. Команды выполняются из корня этого репозитория:

```sh
git clone git@github.com:VSELEZNEV54/TD.git
cd TD
git switch dev
python3 -m server.manage init-env
python3 -m server --host 127.0.0.1 --port 8131
```

- Сайт: <http://127.0.0.1:8131/>
- Список страниц для проверки: <http://127.0.0.1:8131/_pages/>
- Проверка сервиса: <http://127.0.0.1:8131/api/health>
- Панель обращений: <http://127.0.0.1:8131/admin/>

Ключ панели `ADMIN_TOKEN` создается в личном `.env`. Откройте файл в редакторе и введите ключ в панели. `init-env` не перезаписывает существующий `.env`. Обращения сохраняются в `server/data/requests.sqlite3` и переживают перезапуск.

Проверьте главную, девять возможностей с роликами «Было / Стало», инструменты, переключение периодов в тарифах, статьи с закрепленными плашками и контакты. Минимальная ширина телефона: 320 px. Калькулятор считает в браузере, генератор договора скачивает DOCX. Вопросы из FAQ и запросы консультации сохраняются в панели. Email-уведомления из панели пока не подключены.

## 2. Проверить фронтенд на GitHub Pages

Для кликабельной проверки используется отдельная ветка **`gh-pages`**: в ее корне лежит статический экспорт из `dev`, без исходников и серверных данных. Источник Pages: **Deploy from a branch → gh-pages → / (root)**. Адрес просмотра: <https://vseleznev54.github.io/TD/>. Такая публикация не означает приемку: ветка `main` и открытый PR с правками остаются отдельно.

GitHub Pages раздает статические файлы и не запускает Python или SQLite. На Pages работают дизайн, анимации, переходы, калькулятор и скачивание договора. Форма в этой демонстрации показывает контактную почту; прием обращений и `/admin/` проверяются через запуск из раздела 1 или на своем сервере.

Для проекта `TD` внутренние пути должны начинаться с `/TD/`. Обычную папку `site/` нельзя просто опубликовать вложенной папкой: часть ресурсов использует адреса от корня. Экспортировщик готовит отдельную копию с правильными путями и `noindex`, не меняя `site/`:

```sh
python3 deploy/pages.py .pages-preview/TD --base-path /TD/
python3 -m http.server 8132 --directory .pages-preview
```

Откройте <http://127.0.0.1:8132/TD/>. Сборщик проверяет ссылки и отказывается перезаписывать существующую папку. Для повторной проверки задайте новое имя выходной папки.

### Публикация принятой версии после переноса в main

1. Перенесите принятую ветку `dev` в `main` через Pull Request.
2. Откройте **Settings → Pages → Build and deployment → Source → GitHub Actions**.
3. Откройте **Actions → Проверка и пакеты TeacherDesk → Run workflow**.
4. Выберите ветку `main`, включите параметр **Опубликовать фронтенд на GitHub Pages** и запустите workflow.
5. Дождитесь успешного задания `publish`. Ссылка появится в результате запуска. Стандартный адрес проекта: <https://vseleznev54.github.io/TD/>.

Обычный push в `dev` или `main` только проверяет проект и создает артефакты, без публикации. Ручной запуск становится доступен после появления файла workflow в основной ветке. Новый экспорт показывает текущий сайт; архив прототипа в исходниках сохраняется.

Описание механизма: [GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages), [публикация через Actions](https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages).

## 3. Передать фронтенд и бэкенд на свой сервер

Соберите ZIP с готовыми страницами и серверной частью:

```sh
python3 deploy/package.py dist/teacherdesk-server.zip
```

Архив содержит папку `teacherdesk/` с `site/`, `server/`, `deploy/`, Docker, примером настроек и инструкциями. Личные настройки, базы, обращения и рабочие материалы в него не попадают. Существующий ZIP не перезаписывается.

После каждого успешного запуска Actions такой же пакет можно скачать в **Artifacts → teacherdesk-server**. Артефакт `github-pages` содержит отдельную статическую копию для Pages.

Для запуска распакуйте **всю** папку `teacherdesk/`, создайте `.env`, укажите домен в `PUBLIC_ORIGIN` и запустите:

```sh
python3 -m server.manage init-env
docker compose up -d --build
```

Публичный корень сайта: только `site/`. Папки `server/`, `deploy/`, `.env` и данные находятся рядом, вне публичного корня. Не размещайте `build/`, `prototype/` и исходники репозитория в каталоге, который раздает nginx.

Подробно о Docker, варианте без Docker, HTTPS, ключе панели, переносе обращений и резервных копиях: [docs/backend.md](docs/backend.md). Настройки nginx и проверка домена: [docs/pamyatka-servera.md](docs/pamyatka-servera.md).

## Сборка и проверки

Готовые страницы уже включены в репозиторий. Для изменения контента:

```sh
python3 build/build.py
python3 build/sync_home.py
python3 -m unittest discover -s tests -v
```

Обычная сборка сохраняет все страницы для просмотра. Режим `--release` удаляет страницы со статусом `example`; его используют отдельно после приемки контента и юридических документов. Текущий пакет для проверки собирается без `--release`.

Подробнее: [генератор страниц](build/README.md), [дизайн-система](docs/dizajn-sistema.md), [факты о платформе](docs/fakty-o-produkte.md).
