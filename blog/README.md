# Контент-завод блога TeacherDesk

Статьи для `/blog/` пишут, проверяют, иллюстрируют и выпускают агенты Claude Code. Владелец смотрит готовое и при желании откладывает статью. Методология взята из редакции «Сайт в порядке» (репозиторий seo-news) и упрощена: меньше агентов, меньше вызовов модели, механику проверяет код, а не модель.

## Как это работает

```
blog/plan.json (60 тем на 3 месяца, график выхода)
        |
        v
/blog-batch  (раз в несколько дней, на Маке с Claude Code)
        |
        |-- zavod.py new      шапка статьи из карточки плана, без модели
        |-- td-blog-writer    текст в Markdown, промпты картинок     1 вызов
        |-- zavod.py lint     длина, символы, ключ, ссылки, факты-стоп  без модели
        |-- td-blog-critic    факты, обещания, вред, дубли             1 вызов
        |      (блокеры -> писатель правит -> критик, максимум 2 круга)
        |-- Figma generate_image  обложка и две картинки
        |-- zavod.py img      обрезка, сжатие, картинка для соцсетей   без модели
        '-- build.py          сборка, коммит в dev
        |
        v
GitHub Actions каждый день в 10:00 по Москве (.github/workflows/blog.yml)
        '-- сборка на сегодня: одобренная статья с картинками выходит в свою дату
```

Статья выходит сама, когда выполнены три условия: `status: approved`, дата из шапки наступила (по Москве), три картинки лежат в `site/assets/img/blog/<slug>/`. До даты статья видна только в превью студии с noindex и пометкой «выйдет 17 ноября».

## Что упростили по сравнению с seo-news

| Было в seo-news | Здесь | Почему |
|---|---|---|
| 5 агентов на статью: планировщик, ресерчер, структуратор, писатель, критик | 2 агента на статью: писатель и критик. Планировщик раз в месяц на 20 тем сразу | Карточка плана уже содержит угол, план разделов и мост в продукт; ресерч нужен только темам с `check: true` |
| Статья в JSON с HTML внутри | Статья в Markdown с шапкой | Меньше токенов на вывод, меньше сломанного JSON |
| Критик проверяет и механику, и смысл, до 3 кругов | Механику проверяет `zavod.py lint` бесплатно, критик только смысл и факты, до 2 кругов | Модель не тратится на подсчет слов и символов |
| Telegram-версия, письма, крон на своем сервере | Нет канала; выход по дате в сборке, ежедневный запуск в GitHub Actions | Нечего сломать на сервере, публикации не нужен коммит |
| 7 вызовов, 200-800 тыс. токенов на статью | 2 вызова, около 175 тыс. токенов и 2-3 минуты; с кругом доработки 4 вызова, около 350 тыс. (пилот 11.11.2026) | Цель владельца: дешевле и быстрее при том же качестве смысла |

Что оставили: файлы на диске равны истине (готовая стадия не повторяется), блокеры отдельно от пожеланий, ссылки только на уже вышедшее, порядок плана равен порядку выхода, соседние темы из разных рубрик.

## Перелинковка

Первый месяц плана (`links: 0`): в тексте ни одной ссылки и промоблока, под статьей нет «Читайте также», в финальном призыве одна кнопка регистрации. Со второго месяца (`links: 3`): от 1 до 3 ссылок в тексте на вышедшие статьи и страницы продукта, блок «Читайте также» включается. Правило проверяет `zavod.py lint`: ссылка на статью, которая выйдет позже, это ошибка.

## Картинки

Три на статью: обложка 16:9 и две в текст 3:2. Промпт пишет писатель, общий стиль бренда дописывает `zavod.py prompt` из `plan.json` (`image_style`). Генерация в Figma, файл «TeacherDesk · Блог · иллюстрации» в команде Moon дизайн-студия, модель в `config.json`. Генерация в Figma списывает AI-кредиты тарифа команды: отдельных платежей нет, пока кредитов хватает. Самая дешевая модель стоит по умолчанию. Обработка без внешних программ: `sips` из macOS, JPEG 1376-1600 px, копия 800 px и картинка для соцсетей 1200 x 630.

В тексте генератор ставит картинки сам: фото 1, кадр продукта, фото 2, кадр продукта. Кадры продукта (живые окна TeacherDesk по рубрике) остались из дизайн-системы.

## Команды

```
python3 blog/zavod.py plan          даты по графику, проверка плана, blog/plan.md
python3 blog/zavod.py status        где каждая статья, сколько в буфере
python3 blog/zavod.py next 5        что делать следующим
python3 blog/zavod.py lint --all    проверить все статьи
python3 build/build.py --date=2026-12-01   посмотреть сайт таким, каким он будет в этот день
```

В Claude Code: `/blog-batch` довести следующие статьи до готовности, `/blog-batch probnyj-urok` одну статью, `/blog-plan` темы на следующий месяц.

## Ручное управление

- Отложить статью: в шапке `status: hold`. Вернуть: `status: approved`.
- Поправить текст после одобрения: правьте файл, статус оставьте. Выйдет в свою дату уже с правкой.
- Сдвинуть весь график: поменяйте `schedule` в `plan.json` и запустите `python3 blog/zavod.py plan` и `python3 blog/zavod.py redate`. Вышедшие статьи не двигаются.
- Снять вышедшую статью: `status: hold`, сборка и выкладка уберут страницу.

## Файлы

| Путь | Что внутри |
|---|---|
| `blog/plan.json`, `blog/plan.md` | Карточки тем и график; таблица для чтения собирается из json |
| `blog/metodika.md` | Правила статьи для писателя и критика |
| `blog/config.json` | Файл Figma, модель картинок, размер пакета, разрешение на push |
| `blog/stati/<slug>.md` | Статья: шапка (реестр, SEO, промпты картинок) и текст |
| `blog/proverka/<slug>.json` | Вердикт критика |
| `blog/zhurnal.md` | Журнал прогонов |
| `build/blog_md.py` | Загрузка статей в генератор, статус по дате и картинкам |
| `.claude/agents/td-blog-*.md`, `.claude/commands/blog-*.md` | Агенты и команды |
| `.github/workflows/blog.yml` | Ежедневная сборка и обновление превью |
