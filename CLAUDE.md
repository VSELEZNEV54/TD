# CLAUDE.md

Репозиторий сайта клиента. Студия MOON верстает страницы. Клиент принимает их и сам выкладывает на свой сервер.

Публичные страницы статические: HTML, CSS, JS. Внутренние страницы собирает генератор студии из `build/` (Python 3 без внешних библиотек). Небольшой Python-бэкенд в `server/` принимает вопросы и запросы на консультацию и хранит их в SQLite. Клиент получает готовую `site/` и серверную часть, страницы собирать не нужно. Запуск и перенос описаны в `docs/backend.md`.

---

## Правила репозитория (постоянные)

**Ветки**
- Работа идет только в `dev`.
- В `main` попадает только принятое клиентом, через Pull Request.
- После merge в `main` ставится тег `vX.Y` и запись в CHANGELOG.

**Файлы**
- В публичный корень идет только `site/`. Бэкенд `server/` и настройки запуска находятся рядом, база и секреты вне публичного корня. Не копировать `build/`, `prototype/` и рабочие материалы в публичный каталог.
- Имена: латиница, строчные, через дефис. `price-list.html`, не `Прайс Лист.html`.
- Картинки кладутся уже сжатыми и в нужном размере.
- Макеты Figma только ссылкой в `docs/`.
- Пароли, ключи, доступы к серверу не коммитить никогда. Репозиторий публичный.
- `prototype/`: архив прототипа из КП. Не менять и не удалять, пока он нужен. Корневые `index.html` и `404.html` относятся к старому прототипу. Для текущего сайта на GitHub Pages используем отдельный экспорт `deploy/pages.py` с префиксом `/TD/` и ручную публикацию из Actions. В Pages идет только подготовленная публичная копия сайта.

**Коммиты**
- На русском, формат «Страница: что сделано». Пример: «Главная: блок тарифов».
- Один коммит = одно законченное изменение.

**Тексты в документах**
- Без буквы «е с двумя точками» и без длинного тире.
- Коротко, без канцелярита.

**Без подтверждения нельзя**
- push, merge в `main`, теги, релизы;
- удаление файлов и веток;
- любые изменения настроек репозитория на GitHub.
