# Генератор страниц TeacherDesk

Собирает внутренние страницы сайта в `site/` из реестра, файлов контента и шаблонов. Python 3 без внешних библиотек. На сервер папка `build/` не идет, клиент получает готовую `site/`.

```
python3 build/build.py                 # просмотр у студии: все страницы, примеры закрыты noindex
python3 build/build.py --only=crm      # собрать и проверить одну или несколько страниц
python3 build/build.py --release       # выкладка: только опубликованные страницы
```

Посмотреть локально: `python3 -m http.server 8131` из папки `site/`, затем http://localhost:8131/. Список всех страниц для студии: http://localhost:8131/_pages/.

## Перед выкладкой

Собрать `python3 build/build.py --release` и `python3 build/sync_home.py --release`: примеры, служебный список `/_pages/` и ссылки на неопубликованные страницы уйдут из `site/`. На главной карточки неопубликованных инструментов и статей заменятся опубликованными, кнопки на примеры уберутся. Затем проверить результат: `python3 build/seo_audit.py` должен закончиться строкой «Ошибок нет». После выкладки снова запустить обычную сборку, чтобы вернуть примеры для просмотра.

Проверить выкладку, не трогая `site/`: скопировать `build/` и `site/` во временную папку, собрать там с `--release` и запустить `python3 build/seo_audit.py --site=<папка>/site`.

`seo_audit.py` - технический SEO-аудит готовых HTML: title, description, canonical, robots, Open Graph и файл картинки, один h1 и порядок заголовков, битые и закрытые от индексации ссылки, слэш в конце, глубина от главной и страницы-сироты, микроразметка JSON-LD (обязательные поля, крошки, вопросы FAQ совпадают с видимыми), sitemap.xml и robots.txt, alt и размеры картинок, вес страницы без картинок в gzip (бюджет ТЗ 400 КБ). Настройки сервера и переезд: [docs/pamyatka-servera.md](../docs/pamyatka-servera.md).

## Что где лежит

| Файл | Что внутри |
|---|---|
| `pages.json` | Реестр: адрес, тип, раздел, статус, title, description, h1, подписи для меню и карточек |
| `content/<id>.py` | Тексты страницы: словарь `PAGE`, ключи зависят от типа (ниже) |
| `templates.py` | Шаблоны типов: в каком порядке идут блоки |
| `blocks.py` | Общие блоки: шапка, подвал, крошки, первый экран, FAQ, призыв и т. д. |
| `demos.py` | Живые кадры продукта для первого экрана |
| `schedule.py` | Утвержденный сценарий расписания, общий счетчик, компактные ситуации и сомнения |
| `features.py` | Ролик «Было / Стало» и иллюстрированные карточки остальных возможностей |
| `feature_content.py` | Сценарии, короткие заголовки и описания восьми функций |
| `feature_scene_board.py`, `feature_scene_people.py`, `feature_scene_work.py` | Предметные интерфейсы сцен: доска, ученики, задания, финансы, отчет, ИИ и журнал |
| `films.py` | Мини-ролики функций: 4 главы, сцены из деталей интерфейса |
| `sections.py` | Блоки дизайн-системы: «Знакомо?», ролик, до и после, лента дня, бенто, вкладки, три шага, сомнения, SEO-текст |
| `partials/` | Спрайт иконок, окно «Задать свой вопрос» |
| `build.py` | Сборка, проверки, sitemap.xml, robots.txt |
| `sync_home.py` | Обновляет на главной шапку, подвал, тарифы, JSON-LD, SEO-текст с «Часто ищут» (из `content/home.py`) и версии CSS и JS |
| `og.py` | Картинки для соцсетей 1200 x 630 для каждой страницы в `site/assets/img/og/`, нужен Google Chrome |
| `seo_audit.py` | Технический SEO-аудит собранного сайта, запускать перед каждой выкладкой |

Главную `site/index.html` генератор пока не пишет, ее правят вручную. Общие куски главной (шапка, подвал, тарифы, JSON-LD) обновляет `sync_home.py`. Живые кадры первых экранов внутренних страниц используют классы `pd-*` из `pages.css` и `pages.js`. Ролики возможностей используют общие компоненты `.film` и движок из `home.js`: 6 секунд «Было», затем «Стало», весь цикл 23 секунды. Дополнительные сцены восьми функций описаны в `feature_content.py`, переходы между ними следуют тому же таймлайну через `features.js`. Карточки «Что умеет» и «Другие возможности» используют общие `.pfcs`, `.pfc`, `.pfc__t`, `.pfc__d`.

## Статусы

- `published` - страница готова к выкладке, попадает в sitemap.
- `example` - пример: собирается для просмотра, закрыта noindex, в выкладку не идет.

## Проверки сборки

Сборка останавливается с ошибкой, если title длиннее 65 знаков, description не 140-160 знаков, title или description повторяются, h1 не один, есть буква «е с двумя точками», длинное или среднее тире, восклицательный знак, или ссылка ведет на страницу, которой нет в реестре.

Предупреждения (сборку не останавливают) для опубликованных страниц: в title или h1 нет слов главного запроса `query`; SEO-текст короче нормы типа: посадочная 4 500 знаков, функция 3 500, инструмент 3 000, тарифы 2 500, хаб 1 500.

## SEO

- `query` в реестре - главный запрос страницы, `anchors` - 2-3 варианта анкора из ядра для ссылок на эту страницу из блока «Часто ищут».
- «Часто ищут»: 12 ссылок под SEO-текстом. Набор соседей задан по типу страницы в `templates.py` (`TAGS`), свой набор - ключ `tags` в контенте. Вариант анкора выбирается по паре страниц, поэтому на разные страницы ведут разные анкоры.
- Разметка: Organization, WebPage с `dateModified`, BreadcrumbList, SoftwareApplication с тарифами (цена за месяц) и списком функций, FAQPage из блока вопросов, HowTo из шагов, ItemList у хабов, Article у статей.
- `lastmod` в sitemap.xml и `dateModified` в разметке берутся из даты правки файла контента (у главной из `site/index.html`).
- Картинки для соцсетей: `python3 build/og.py` после правки h1, затем обычная сборка. Если картинки страницы нет, берется общая `og-home.jpg`.
- Каркасы SEO-текстов по типам страниц: [docs/seo-etalony.md](../docs/seo-etalony.md).

## Правила текста

Без буквы «е с двумя точками», без длинного и среднего тире (только дефис с пробелами), без восклицательных знаков, «вы» строчными, деньги «990 руб.», кавычки «елочки», без эмодзи. Бренд пишется TeacherDesk. Неразрывные пробелы после коротких слов и между числом и единицей генератор ставит сам, писать `&nbsp;` не нужно.

Факты о продукте только из [docs/fakty-o-produkte.md](../docs/fakty-o-produkte.md). Цифр пользователей, рейтингов и интеграций не пишем.

В текстах можно использовать HTML: `<a href="/features/raspisanie/">`, `<em class="em">слово</em>` (антиква в заголовке, одно слово или фраза на заголовок), `<b>`, списки. Ссылки внутри сайта только от корня и только на адреса из реестра. Ссылку на страницу-пример помечайте `data-opt`: при выкладке она станет обычным текстом, а не ошибкой сборки. Второстепенные кнопки и ссылки в заголовках блоков на неопубликованные страницы генератор в выкладке убирает сам.

## Ключи контента по типам

Порядок блоков каждого типа задан в шаблонах по [дизайн-системе](../docs/dizajn-sistema.md), раздел 9. Блоки описаны в `sections.py`.

**Общие ключи новых блоков**
```
pains:      «Знакомо?»: h2, lead, msgs=[{who, text, time}] 4-5 шт., total (число на счетчике), count=[2 строки подписи], fix (как решаем)
vs:         до и после: h2, lead, old (подпись «было»), rows=[(задача, как было, как в TeacherDesk)] 4-5 шт.
objections: сомнения: [(сомнение, ответ)] 3 шт.
facts:      полоса фактов под первым экраном: [(значение, подпись)] 4 шт.
seo:        SEO-текст в конце страницы: h2, html (подзаголовки h3, списки, таблицы <table>; объем по типу страницы, см. «SEO»)
tags:       свой набор id для «Часто ищут» (необязательно)
```

**landing** (посадочная): `hero {kicker, lead, demo, second, stickers}`, `pains`, `features {kicker, h2, items}` (вкладки: id функций или (id, текст)), `vs`, `steps {h2, steps=[{title, text}] x3}`, `pricing_h2`, `objections`, `faq`, `related`, `cta {title, second}`, `facts`, `seo`.

**feature** (функция): `hero`, `facts`, `pains`, `vs`, `scenarios {h2, lead, items=[{when, title, text}]}`, `points`, `objections`, `faq`, `cta`, `seo`. Шаблон выводит один ролик «Было / Стало» вместо отдельных сообщений, старого ролика и сравнения; затем четыре ситуации, иллюстрированные карточки и сомнения. Короткие тексты и сцены остальных функций задаются в `feature_content.py`, расписание служит образцом в `schedule.py`. Шаблон автоматически нумерует страницу в общем списке функций и показывает карточки всех остальных опубликованных функций. FAQ и SEO-текст берутся из исходного контента страницы.

**tool** (инструмент): `hero {kicker, lead, cta, trust}`, `tool` (HTML виджета), `wide`, `howto {h2, steps}`, `platform {title, lead, items}`, `extra`, `band`, `objections`, `faq`, `related`, `cta`, `seo`, `ld`, `example_note`.

**hub** (хаб): `kicker, lead, text {kicker, h2, html}, cta, seo`. Карточки раздела собираются из реестра, у функций стопка карточек с главной.

**article** (статья): `lead, author, published, updated, sections=[{h2, html, id}], faq, related, cta`. В html можно вставить `[[promo:id]]`: блок-переход в продукт или инструмент.

**kb** (инструкция): `lead, minutes, steps=[{title, text, shot, icon}], tips_h2, tips, related`.

**pricing**: `kicker, lead, h2, disc_h2, disc_text, discounts, table_h2, table, notes_h2, notes, objections, faq, seo`.

**about**: `kicker, lead, story_h2, story, facts, values_h2, values, contacts_h2, contacts, requisites`. **reviews**: `kicker, lead, note`. **legal**: `updated, html, note`. **notfound**: `lead`.

## Живые кадры (`demo`)

`tl` лента дня, `debt` долги и напоминания, `hw` проверка задания, `ai` ассистент печатает план, `week` неделя с переносом урока, `board` урок с доской, `phone` телефон с уведомлением, `card` карточка ученика, `cabinet` кабинет ученика, `report` отчет родителю, `journal` журнал, `desk` главный экран кабинета, `trial` пробный период.

## Каталог инструментов

Бесплатные инструменты на главной и в хабе: `kalkulyator` и `dogovor`. Список задан в `templates.TOOLS`. Формы работают локально, договор выгружается в DOCX.

`tablica-ucheta` и `shablon-raspisaniya` сохраняют прежние URL, но имеют тип `table`: это страницы интерфейса TeacherDesk со сравнением ручной таблицы и пробными 14 днями. Их собирает `table_pages.py`; Excel-файлы больше не создаются сборкой.

Старые страницы плана урока и заданий имеют тип `ai-access` и ведут к ИИ в платформе. Публичный ИИ-генератор не включать без серверного учета лимитов: счетчик в браузере не обеспечивает ограничение между сессиями.

Страница `kontakty` типа `contacts` собирается через `contact_page.py` из опубликованных почт и реквизитов. Форма отправки без обработчика не используется.

## Общие шаблоны каталога, тарифов и статей

`tools_hub.py` собирает одну сетку инструментов, блок о сервисе и карточки возможностей. `pricing_page.py` вместе с `pricing.css` и `pricing.js` отвечает за ранний выбор периода и синхронные цены в планах и сравнении. `article_page.py` и `article.css` собирают широкую обложку, текст слева, правый сайдбар, три иллюстрации и FAQ из видимого блока главной. Общие шрифты берутся из существующих переменных сайта.

Плашки пробного периода и консультации в статье закреплены вместе под шапкой, в пределах текста статьи. Короткое содержание прокручивается отдельно. Для GitHub Pages используется `deploy/pages.py`, который меняет только отдельную копию с префиксом проекта; исходный `site/` остается для сервера с корневыми URL. Полные команды проверки и публикации находятся в корневом README.
