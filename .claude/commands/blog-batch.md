Ты оркестратор контент-завода блога TeacherDesk. Работаешь в корне репозитория TD (папки `blog/`, `build/`, `site/`). Все общение и артефакты на русском. Пиши в чат коротко: какой этап идет и чем закончился.

Аргументы: **$ARGUMENTS**

## 0. Подготовка

- `git status --short` и `git branch --show-current`: работаем только в `dev`. Чужие незакоммиченные правки не трогай и в коммит не бери.
- Прочитай `blog/config.json`. Если `push: true`, сначала `git pull --ff-only origin dev`; не вышло: остановись и сообщи владельцу.
- Задания: `python3 blog/zavod.py next <N> --json`, где N из аргумента или `batch` из конфига. Если в аргументах слаги, работай только с ними.
- Файлы на диске равны истине: стадию, результат которой уже есть, не повторяй (флаги `has_draft`, `has_verdict`, `approved`, `has_images`).

## 1. Текст

Для каждой темы без черновика: `python3 blog/zavod.py new <slug>`. Затем субагенты `td-blog-writer`, по одному на статью, не больше `parallel` из конфига одновременно. В промпте только слаг. Черновик есть, но `lint` с ошибками: тот же агент в режиме правок с выводом линтера.

После каждого писателя `python3 blog/zavod.py lint <slug>`. Остались ОШИБКИ: одна попытка правок у писателя. Не помогло: статья ждет, перейди к следующей и отметь в журнале.

## 2. Проверка

Для статей без ошибок линтера и без одобрения: субагенты `td-blog-critic` параллельно. Затем `python3 blog/zavod.py verdict <slug>`.

- `ЗЕЛЕНО`: статус станет `approved`.
- `НА ДОРАБОТКУ`: писатель в режиме правок, в промпт передай `blockers` из `blog/proverka/<slug>.json` дословно. Потом критик еще раз и снова `verdict`. После второго круга без одобрения статус станет `hold`: владелец решит сам.

## 3. Картинки

Для одобренных статей без картинок, по очереди `cover`, `1`, `2`:

1. `python3 blog/zavod.py prompt <slug> <n>`: полный промпт с общим стилем и размер.
2. Инструмент Figma `generate_image`: `fileKey` из `figma_file` конфига, `model` из `image_model`, ширина и высота из вывода. Если Figma просит сессию: `create_session` с этим `fileKey` один раз за прогон.
3. Посмотри миниатюру. Текст или буквы на картинке, искаженные руки и лица, логотипы, сцена не по смыслу: сгенерируй еще раз один раз, при повторе добавь `image_model_fallback`.
4. Скачай `image.url` отдельной командой на каждую картинку: `curl -sS -f -L --retry 3 --retry-delay 5 --retry-all-errors --max-time 40 -o <папка-для-временных-файлов>/<slug>-<n>.jpg "<url>"`. Адрес пиши в команду целиком. Не собирай пары «картинка, адрес» через `set -- $p`: в zsh строка не делится на слова, в адрес уходит пустой id и Figma отвечает 404.
5. `python3 blog/zavod.py img <slug> <n> <файл>`.

Figma не отвечает или кончились кредиты: не останавливай прогон. Статья остается одобренной без картинок и не выйдет, пока их нет. Отметь в журнале.

## 4. Сборка и журнал

- `python3 build/build.py`. Ошибки сборки по твоим статьям исправь через писателя; чужие ошибки не трогай, сообщи.
- `python3 blog/zavod.py status | tail -15`: проверь буфер.
- Допиши в `blog/zhurnal.md` по строке на статью: дата прогона, слаг, итог (одобрена, отложена, ждет картинок), кругов критика.

## 5. Коммит

- Добавляй только свои файлы, поименно: `blog/stati/<slug>.md`, `blog/proverka/<slug>.json`, `blog/zhurnal.md`, `site/assets/img/blog/<slug>/`, собранные `site/blog/`, `site/sitemap.xml`, `site/_pages/`. Никогда `git add -A`.
- Коммит: `Блог: статьи в буфер (<слаги через запятую>)` и строка соавторства из системных правил, если она задана.
- `push: true` в конфиге: `git push origin dev`. Иначе не отправляй и напиши, что коммит локальный.
